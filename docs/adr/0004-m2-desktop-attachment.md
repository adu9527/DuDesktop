# ADR 0004：M2 桌面附着与 Shell 状态恢复

- 状态：已采纳（部分验收受环境阻塞）
- 日期：2026-11-11
- 关联：`ARCHITECTURE.md` 第 4、8 节；`docs/DEVELOPMENT_PLAN.md` M2

## 背景

壁纸必须位于桌面图标层之下、覆盖显示器完整边界，并在 Explorer 重启、会话锁定、休眠、显示变化与宿主/主进程异常后恢复。Windows 没有公开的“桌面壁纸层”API，社区广泛使用 `Progman` 的 `0x052C` 消息与 WorkerW 层级。

## 决策

1. **非公开协议集中隔离**：`Progman 0x052C`、`WorkerW`、`SHELLDLL_DefView`、`SysListView32` 与 `WM_COMMAND 0x7402` 只出现在 `crates/shell-win/src/desktop.rs`；失败返回 `AttachError` 明确原因，不假定所有 Windows 版本行为一致。
2. **完整显示器边界**：壁纸使用 `MONITORINFOEXW.rcMonitor`，不使用预览窗口的工作区；负坐标通过父窗口屏幕原点换算。显示器身份使用设备名（`\\.\DISPLAYn`），索引仅作回退。
3. **父子校验与样式**：附着前将窗口切换为 `WS_CHILD`（否则 `GetParent` 返回所有者而不是父窗口），`SetParent` 后必须校验 `GetParent`；解除附着时恢复顶层样式并隐藏。
4. **失效与重建**：Explorer 销毁父窗口会连带销毁子窗口，因此检测到窗口失效时重建窗口与 mpv 播放器（旧 `wid` 不可复用），而不是复用已销毁句柄。附着期间保留 2 秒低频恢复看门狗，系统事件（显示变化、会话变化、电源广播）即时触发复检；未附着/关闭时不启用该唤醒。
5. **静态回退**：附着失败时不创建可见窗口、释放不可见解码资源，让系统静态壁纸继续显示；`AttachmentState::Fallback { reason }` 上报原因，恢复成功后自动重新加载素材。产品不修改系统壁纸配置，因此无需恢复系统壁纸值。
6. **图标状态**：查询 `SysListView32` 实际可见性；`0x7402` 是切换命令，必须查询后再决定是否发送，重复设置同值不发命令。M2 不默认隐藏图标；隐藏入口在 M3 首次引导中由用户选择。
7. **修改日志**：任何 Shell 修改前先写 `ShellStateJournal`（键、原值、应用值、会话所有者、恢复状态），原子替换写入；同键重复记录保留首次原值；损坏日志改名保留后继续。恢复操作必须幂等。
8. **资源归属**：壁纸窗口、mpv 上下文与附着状态由宿主实例持有；主进程只下发完整期望状态。宿主被立即终止时窗口随进程销毁，系统桌面不受影响；下次启动由期望状态重建。

## 后果

- 正面：桌面壁纸覆盖完整屏幕（含任务栏区域），多屏/负坐标有明确换算；Explorer 重建可恢复；系统壁纸不被修改，回退简单可靠。
- 成本/风险：`0x052C` 与 WorkerW 层级可能随 Windows 更新变化，需要版本矩阵复测；2 秒低频看门狗在附着期间产生少量唤醒；图标切换命令是兼容操作，必须查询后使用。
- 未验证：真实 Explorer 重启、锁屏/解锁、休眠恢复、热插拔、分辨率/DPI 变化、Show Desktop/任务视图/虚拟桌面、多屏与多厂商矩阵。执行步骤见开发计划 M2 表。

# ADR 0006：M4 画质策略、配置 v2 与 Eco 静态呈现

- 日期：2026-11-11
- 状态：已接受；核心实现、5 分钟 Eco 桌面测量与隔离安装/卸载验证通过；真实菜单点选、多屏/多厂商与真实电源规则链路待覆盖

## 背景

M4 需要让用户控制画质与效果，同时保证关闭效果后真实降低开销。此前的配置只有 v1（Dock、壁纸、首次引导），宿主只有 `paused` 一个暂停维度，无法区分：

- 用户主动暂停（保留当前帧，等待用户恢复）；
- Eco/自动规则要求的静态呈现（停在当前帧，但用户并未暂停）；
- 停止壁纸（释放播放资源，交给系统静态桌面）。

如果把这些状态合并成一个布尔值，就无法验证“停在当前帧”与“仍在持续解码”，也无法保证自动降档不覆盖用户意图。

## 决策

1. **用户意图与有效策略分离**
   - `QualityProfile`（`policy.rs`）是持久化用户意图：预设、Custom 效果、自动规则开关、逐显示器覆盖。
   - `EffectivePolicy` 是纯函数输出：某一显示器、某一时刻的实际播放意图、UI 动画/阴影/模糊、生效原因与等待原因。
   - 自动规则只改变 `EffectivePolicy`，从不回写 `QualityProfile`。关闭规则或条件消失后从用户意图重新求值。

2. **自动规则只降档，并带迟滞/冷却**
   - 初始参数：进入 1.5 秒，恢复 30 秒，切换冷却 10 秒；作为工程初值，后续用实测调整并记录理由。
   - 降档原因优先级：远程会话 > 全屏 > 完全遮挡 > 指定前台应用 > 电池/节能。
   - 规则作用域是壁纸所属显示器；前台窗口在其它显示器时不降档。
   - 所有规则可单独关闭；全部关闭后停止 2 秒采样定时器，不保留高频遥测。
   - 平台信号由 `shell-win/src/system_state.rs` 提供：窗口矩形与 `rcMonitor`/`rcWork` 比较（2 px 容差）、DWM cloaked、最小化、Shell 类名排除、前台进程名、电源与远程会话。不截屏、不读取窗口内容。

3. **协议 v4 新增静态呈现模式**
   - `RenderOptions.playback = animate | static`；`InstanceStatus.render` 回报实际值，`video_position_ms` 供验收观察。
   - `paused=true` 仍表示用户暂停，优先级高于自动策略。
   - `Static` 的宿主实现：确认首帧/硬解后对 mpv 设置 `pause=yes`，保留播放器与当前帧；播放位置不推进、无持续解码。恢复 `animate` 时解除该策略性暂停。
   - 停止（`Source::None`）仍释放播放器；`Static` 不得被当作“已释放资源”，验收以 `player_active` 与播放位置/CPU 为准。

4. **配置 v2 的可回滚写入**
   - 仍使用 `%APPDATA%\DeskShell\config.toml`；写入前把旧文件复制为 `config.toml.prev`，主文件损坏时优先从 `.prev` 恢复并把损坏文件改名保留。
   - v1→v2 迁移前写 `config.v1-<时间>.bak`；迁移失败不吞掉警告。
   - 保存时以已知字段覆盖旧值、递归保留未知字段/表；高于程序版本只读；临时文件 `fsync` 后 rename。
   - 安装目录使用 `%LOCALAPPDATA%`；用户配置不随安装/卸载默认删除。

5. **效果开关只覆盖已交付能力**
   - 已交付：UI 动画（Dock 鱼眼/悬停）、壁纸播放、面板阴影。
   - 阴影是独立 GDI 分层窗口：静态 DIB + `UpdateLayeredWindow`，不参与 DComp 交换链；`WS_EX_TRANSPARENT` + `WM_NCHITTEST=HTTRANSPARENT` 保证点击穿透；关闭时销毁窗口与 DIB。
   - 模糊未交付：菜单显示置灰原因“需 M5 渲染管线”，不提供无效开关；不把阴影或半透明冒充背景模糊。
   - 效果关闭后不保留对应窗口/位图/动画定时器；自检覆盖阴影创建、穿透与释放。

6. **性能验收口径**
   - 正式测量只接受 release 构建；`perf-check` 启动真实 `deskshell app` + 宿主进程树，默认 Eco 静态图片、桌面附着、300 秒、预热 20 秒。
   - CPU 为 `GetProcessTimes` 的 kernel+user 执行时间，同时报告单核百分比与整机归一百分比（除以逻辑 CPU 数）。
   - DWM 时间尝试单独记录；本机 `dwm.exe` 受保护导致读取失败时必须在报告中说明，不得用其它数字替代。
   - GPU 时间当前未采集；M5 引入统计后单独报告 p95/p99 与掉帧，不能与 CPU 混为一个指标。
   - 短测必须标注“不能替代 5 分钟验收”。

## 后果

- 自动降档行为可解释、可测试，且不会破坏用户配置。
- Eco 视频可以“保留画面但停止推进”，与用户暂停、停止释放资源三者语义清晰。
- 配置写入多了一次备份复制；在高频保存场景下会增加少量 I/O，但配置修改是低频用户操作。
- 面板阴影使用独立分层窗口，不引入 DComp 效果依赖；它与背景模糊是两种能力，M5 不得用其冒充模糊验收。
- 5 分钟 CPU 目标、真实全屏/电池/RDP 规则、安装卸载仍需实机验收；当前不得标记 M4 全部完成。

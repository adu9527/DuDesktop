# ADR 0008：M6 控制通道、诊断、素材迁移与发布边界

- 日期：2026-11-11
- 状态：已接受；CLI、诊断、受管理素材、安装回滚与本地候选包已实现；24/72 小时长稳、多厂商矩阵、在线更新与签名发布未完成

## 背景

M6 需要长期可用、可自动化、可诊断、可回滚，并且发布包必须真实处理 GPL libmpv 的许可与源码提供。
同时要避免为了“发布形态”引入不必要的服务、网络更新器或跨进程共享状态。

## 决策

1. **控制通道使用单实例命名管道**
   - 固定名称 `\\.\pipe\DeskShell.Control`；只允许当前用户，`PIPE_REJECT_REMOTE_CLIENTS`。
   - 请求/响应为 JSON；命令只描述用户意图（状态、暂停/恢复、设置壁纸、预设、恢复桌面、退出、诊断/素材导出）。
   - 管道线程只收发；请求通过事件与 `WM_APP_CONTROL` 交给 UI 线程，复用托盘/设置的同一状态修改路径，避免多线程改窗口与宿主监督器。
   - 退出码稳定：0 成功、2 参数错误、3 未运行、4 拒绝、5 超时/传输失败；`--json` 为机器可读输出。
   - 不把控制通道当作第二个播放 IPC；壁纸数据仍走宿主协议。

2. **诊断采用本地滚动 JSON 行日志**
   - `%LOCALAPPDATA%\DeskShell\logs\deskshell.log`，2 MiB 滚动、最多 5 个历史文件；记录启动、配置警告、宿主连接/失败、策略变化、控制命令/响应与退出。
   - 导出由用户主动触发，合并应用状态、宿主快照、Windows build、DXGI 拓扑与最近日志；原子写入。
   - 日志不作为控制流；写入失败只回退 stderr，不影响主功能。

3. **素材明确区分引用与受管理导入**
   - 默认引用原文件；`--managed` 复制到 `%LOCALAPPDATA%\DeskShell\assets` 并记录 `original_source`。
   - `last_good_source` 在当前素材缺失时回退；不移动、不删除用户原文件。
   - 配置继续使用 `.prev` 与迁移 `.bak` 支持回滚；`assets export` 导出配置快照、素材与 manifest，导入复用 `set-wallpaper --managed`。

4. **更新采用手动安装 + 上一版本备份，不做无后端支撑的自动更新开关**
   - 安装器在覆盖前把旧 exe/宿主/libmpv 备份到 `InstallDir\previous`；`rollback.ps1` 恢复。
   - 默认拒绝替换正在运行的程序，避免播放中替换已加载 DLL；`-Force` 才先停止。
   - 本阶段没有在线更新通道、稳定/实验分流或灰度能力，因此不提供“自动更新”UI 假开关；稳定/实验边界只由版本号与候选包说明表达。
   - 后续若引入更新器，必须单独 ADR，覆盖签名、回滚、网络失败与 DLL 替换时机。

5. **GPL libmpv 许可与源码提供随包落地**
   - 分发固定 libmpv 二进制，记录版本、上游 release/commit、SHA-256。
   - 包内包含 `GPL-2.0.txt` 与 `THIRD-PARTY-NOTICES.txt`，提供上游源码地址与三年源码提供声明；不把许可证留作 TODO。
   - 只产出本地候选包；没有签名证书与发布凭据时不伪造签名或兼容性结果。

## 后果

- CLI 与诊断可在不引入网络服务的前提下自动化与排障；控制通道故障不会影响播放 IPC。
- 受管理素材与缺失回退降低“用户移动/删除原文件导致黑屏”的风险，但导出/导入仍以文件复制为主，不做云同步。
- 手动更新与回滚可审计；没有自动更新器意味着用户需自行下载候选包，符合当前发布能力边界。
- 24/72 小时、NVIDIA/Intel/混合显卡、多屏/DPI、HDR 与真实设备失效仍需外部环境与时间，未完成前不得宣称长期版正式通过。

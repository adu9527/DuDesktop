# ADR 0002：M1 命名管道 IPC 与宿主监督

- 日期：2026-11-11
- 状态：已接受；M1 核心验收通过

## 背景

M0 阶段主进程通过子进程 stdout 读取一条 JSON 握手，只用于开发自检，不具备持续通信、请求关联、版本控制、超时、断开恢复或访问控制。M1 需要独立壁纸宿主长期运行，并在宿主崩溃、驱动/播放器故障或主进程退出时保持桌面可用且不留下孤儿进程。

## 决策

1. **传输**：主进程创建本机命名管道服务端，宿主以客户端连接。
   - 管道名包含主进程 PID、时间戳和序号，通过命令行传给宿主；名称不作为安全边界。
   - DACL 使用 SDDL `D:P(A;;GA;;;OW)(A;;GA;;;SY)`，仅允许对象所有者（当前用户）与 SYSTEM，并设置 `PIPE_REJECT_REMOTE_CLIENTS`。
   - 字节模式 + 自有帧格式：`u32 小端长度 + JSON`；总帧上限 256 KiB（载荷 262140 字节）。读取长度前缀后先校验上界，再分配缓冲区。
   - 使用重叠 I/O 与每方向事件实现有界读取/写入；超时后 `CancelIoEx` 并回收未完成操作，避免缓冲区释放后仍被内核写入。

2. **协议**：`protocol` crate 定义版本化信封，传输层不依赖 UI/GPU。
   - 字段：`protocol_version`、`host_generation`、`config_version`、`request_id`、扁平化 `body`。
   - 消息：`hello`、`request`、`response`、`event`；响应通过 `request_id` 关联。
   - 宿主代次每次启动递增，主进程丢弃代次不匹配的消息；配置版本单调递增，宿主拒绝小于已应用版本的请求。
   - 命令使用完整期望状态 `apply_state`，重复应用同一配置安全；重连后监督器自动重发最新期望状态。
   - 扁平化信封中的 snapshot 使用 `generation` 字段而不是 `host_generation`，避免 JSON 键冲突；协议测试覆盖请求与响应往返。

3. **超时与失败语义**：
   - 连接 5 秒、握手 5 秒、普通命令 5 秒、应用配置 20 秒（开发 CLI 为 30 秒）。
   - 命令超时或管道断开视为宿主会话失效：监督器取消读取、终止宿主进程并按退避重启；等待中的调用返回 `timeout`/`disconnected`。
   - 宿主未连接或已进入失败状态时，命令立即返回 `not_ready`，不阻塞主进程。

4. **监督与生命周期**：
   - 监督线程负责启动、握手、读取事件与重启；命令由调用线程经互斥写入，响应由读取线程分发，因此主进程 UI 不被宿主阻塞。
   - 指数退避：500 ms、1 s、2 s、4 s，最多 4 次；连接稳定运行 30 秒后清零失败计数；超过上限进入 `failed`，不再重启风暴。
   - 主进程为宿主分配 Job 对象并设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，作为主进程异常退出时的系统级兜底。
   - 宿主打开父进程句柄并等待；父进程退出或管道断开时取消 I/O、停止 mpv、销毁窗口并退出。正常退出先发送 `shutdown`，超时后强制终止。
   - 宿主主线程拥有窗口与 mpv 实例；管道读取、mpv 事件与父进程监视线程只向自动重置事件队列投递消息。空闲时无限等待，不忙轮询。
   - 视频等待首帧时使用 250 ms 有界等待看门狗；超时 5 秒判定解码失败并进入明确错误/静态回退。

5. **测试故障注入**：`wallpaper-host --fault <mode> --fault-generation N` 仅用于 `host-check`，可注入非法协议、超限消息、无响应与断开。故障可只作用于首个代次，用于验证恢复；也可配合 `max_attempts=0` 验证有限失败。

## 证据

验证环境：Windows 11 build 26200，AMD Radeon 780M，单屏 2560×1440@144、125% DPI。

`scripts/dev.ps1 host-check` 实测通过：

- 杀死宿主后主进程命令在 0 ms 返回 `NotReady`，监督器以新代次恢复，且不重新下发命令即可按期望状态恢复播放。
- 主进程正常退出与强制终止后均无遗留 `wallpaper-host.exe`。
- 非法协议与断开只注入首代次时，第二代次恢复并继续播放。
- 超限消息（262141 > 262140）与无响应宿主进入有限失败状态，未形成重启风暴。
- 双实例同时播放，暂停/停止一个实例不影响另一个。

## 已知限制

- 仅验证当前用户单会话访问控制；未创建第二用户或跨会话攻击测试。
- 未做长时间（24/72 小时）句柄、内存与管道重建增长测试。
- 命令超时统一终止宿主，未实现单实例级恢复；M4 可按故障域拆分。
- 故障注入开关存在于生产宿主二进制中，但只能通过命令行启用，不属于正常用户入口。
- 主进程退出若恰逢宿主启动/连接阶段，最坏等待一个连接超时；孤儿清理由 Job 对象和父进程监视保证。

## 后果

- M1 的命令/状态模型可直接复用于 M4 的 CLI 与每显示器控制。
- `protocol` 的版本、大小限制与单调配置版本成为后续兼容基线。
- 宿主故障被隔离在独立进程；驱动级崩溃不等同于可完全隔离，仍需长期兼容矩阵验证。
